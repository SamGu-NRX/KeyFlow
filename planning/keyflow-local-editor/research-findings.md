## G. Baseline blockers (numbered, with evidence)

1. **Every Next CLI command is broken at config load.** `next.config.mjs` line 4 imports `@svgr/webpack`, which is declared in neither dependencies nor devDependencies of `package.json`; pnpm's strict layout doesn't expose it. `pnpm run build` and `pnpm run lint` both die with `ERR_MODULE_NOT_FOUND: Cannot find package '@svgr/webpack'` (exact output in F). `pnpm dev` uses the same loader path (expected, not executed).
2. **`eslint` is not a devDependency**, yet `lint` script runs `next lint` and `.eslintrc.json` extends `next/core-web-vitals` — untestable until blocker 1 is cleared (fact: package absent from package.json).
3. **`tailwindcss-animate` is referenced but not installed**: `src/app/globals.css` has `@plugin "tailwindcss-animate";` and `tailwind.config.ts` has `plugins: [require('tailwindcss-animate')]` (the latter currently inert, see 4). Whether `@plugin` fails the CSS build is untested — the build never reaches the CSS stage (fact: package absent).
4. **Tailwind v3/v4 drift.** `tailwindcss 4.0.9` + `@import "tailwindcss"` (v4 mode) ignores `tailwind.config.ts` without an `@config` directive; no `@config` exists in `globals.css`. The v3 config's `darkMode: 'class'` and shadcn hsl color mapping are therefore not applied; meanwhile `globals.css` carries **two overlapping token sets** (HSL set in `@layer base`, later plain-`:root` oklch set that wins the cascade) — duplication the spec writer must reconcile.
5. **Quality gates are disabled in config.** `next.config.mjs` sets `eslint.ignoreDuringBuilds: true` and `typescript.ignoreBuildErrors: true` — even once building, `next build` will not catch type or lint errors. (`tsc --noEmit` currently passes and must be run explicitly.)
6. **Tauri dev URL mismatch.** `tauri.conf.json` `devUrl: "http://localhost:1420"` vs the dev script `next dev --turbo` which serves on 3000 by default — `pnpm tauri dev` would point the window at a port nothing serves.
7. **Tauri dist mismatch.** `tauri.conf.json` `frontendDist: "../dist"` vs Next's actual output (`.next`; `out/` only with `output: 'export'`, which is not configured) — the bundle step has no `dist` to consume.
8. **No test/CI scaffolding whatsoever.** No test runner, no test files, no `.github/workflows`, no hooks (all absent — section D). The build/test/QA bar starts from zero.
9. **Rust side unpinned and unbuildable here.** `src-tauri/Cargo.lock` absent (deps resolved at build time), and this sandbox has no `rustc`/`cargo`/`rustup` and none of `webkit2gtk-2.4`, `gtk+-3.0`, `libsoup-3.0` (section F). (`apt-get` and passwordless sudo exist if the operator authorizes installs.)
10. **Marketing overstates current behavior.** README claims "GitHub Copilot-style autocomplete", "Prettier-level, fully customizable auto-formatting", "Uses RAG … to train on your past writing", "Seamless integration across all Windows apps", and "KeyFlow uses Next.js 15" (actual: `next 14.2.24`; README's own requirements say Next.js 14). Lander pricing promises `10 RAG Training Documents`, `Unlimited RAG Training`, `Sync Across 3 Devices`, `Admin Dashboard`; CTA claims `Join thousands of early adopters`; FAQ claims `We tested it on a laptop from 2015`. No product code exists beyond the `greet` demo (section E), all lander buttons are inert, and README images are `via.placeholder.com` placeholders.
11. **Stale/broken references.** `tsconfig.json` `include` lists nonexistent `src/components/page.jsx`; `components.json` aliases (`@/lib/utils`, `@/components/ui`) point to absent directories; `layout.tsx` metadata is still `Create Next App` / `Generated by create next app`; `public/` holds only template `tauri.svg`/`vite.svg`.
12. **Accessibility/motion gaps in the lander** (mapping facts for the QA bar): typewriter and cursor `setInterval` loops and framer-motion animations run unconditionally with no `prefers-reduced-motion` handling; the FAQ accordion `<button>` sets no `aria-expanded`/`aria-controls`; decorative check/chevron SVGs have no `aria-hidden`.
