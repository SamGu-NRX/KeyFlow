Ship the local writing editor KeyFlow advertises

The committed app is a marketing lander and the Tauri greet demo. This spec turns it into a working local-first writing product — document library, autosaving editor with revisions, safe import/export, deterministic local suggestions, settings with a local-data control, and marketing that tells the truth — delivered as milestone commits on one draft PR.
KeyFlow advertises an AI writing tool. The repo delivers a joke-heavy lander whose every button is inert, plus the Tauri template greet command. This build makes the product real — scoped deliberately to a user-opened, local-first writing editor.

The product this spec ships: a document library, an editor with autosave acknowledgements, bounded revision history and undo, import/export with explicit safety rules, one deterministic local suggestion adapter behind an explicit confirm-to-apply flow, user-triggered formatting, and settings that include a clear-local-data control. The browser flow is the product and must actually run. The Tauri desktop shell gets a correct config and unit-tested platform-independent logic, but packaging a desktop window is an unrun arm on this Linux sandbox and will be recorded as such — never as a passed build.

KeyFlow is a destination the user opens to write. No ambient application capture, no keystroke injection, no global hooks, no “works in every app” integration, no cloud AI, no network calls from product code, no personal writing corpus. Those belong to a different product; this spec deliberately does not compete with Caret’s system-wide capture.

Load-bearing assumption. The task’s premise is that a local editor (browser now, desktop shell later) is the useful product KeyFlow should be. That premise would be wrong if the operator actually needs system-wide capture or cloud sync — both are explicit non-goals here, and the marketing rewrite will say so. Confirming evidence: the shipped editor passes the full local test/QA bar with zero network calls. Breaking evidence: a hard requirement for cross-device sync or ambient capture, which would need a different spec.

What approval starts: one draft PR from obv/products-l4-keyflow-local-editor-20261010 into main, built as two to four pushed milestones — (1) baseline unblock plus a tested document model, (2) working library/editor with recovery, (3) formatting, suggestions, and truthful marketing, (4) settings, Rust core, and the full QA sweep. All data stays on-device; nothing alters text before an explicit confirmation; every claim on the lander maps to shipped code or is labelled proposed.

Document model and contracts

One TypeScript module is the single source of truth for document shape. Every entry point that receives unknown bytes — a fresh IndexedDB read, an import file, a desktop payload — funnels through the same validator. Revisions are full-text snapshots, bounded, newest-first: predictable storage and reliable restore, and diffs are not worth the complexity for local writing docs.

// The single source of truth for document shape. Everything unknown flows // through parseStoredDocument — fresh storage reads, imports, desktop payloads. export const SCHEMA_VERSION = 1; export const MAX_REVISIONS = 50; export interface Revision { id: string; // `${doc.revCounter}` — stable across storage roundtrips text: string; // full snapshot (bounded count keeps storage predictable) createdAt: string; // ISO 8601 UTC origin: "autosave" | "manual" | "import" | "restore" | "format" | "suggestion"; } export interface KeyflowDocument { schemaVersion: 1; id: string; // uuid v4, generated at creation title: string; // trimmed; empty becomes "Untitled document" text: string; createdAt: string; updatedAt: string; revCounter: number; // monotonic — never reused, even after revision trimming revisions: Revision[]; // newest-first, length ≤ MAX_REVISIONS } // Validates unknown input; never trusts shape. Corrupt records are quarantined // (surfaced in Settings), never thrown away silently, never crashed on. export function parseStoredDocument(input: unknown): Result;

Persistence: one adapter interface, three implementations

The storage boundary is one interface. The browser adapter is the product path and is exercised for real; the desktop adapter mirrors it over Tauri commands; the fake makes failure deterministic in tests.

export interface StorageAdapter { listDocuments(): Promise; getDocument(id: string): Promise; putDocument(doc: KeyflowDocument): Promise<{ savedAt: string }>; // ← the autosave ack deleteDocument(id: string): Promise<void>; getMeta<T>(key: MetaKey): Promise<T | null>; setMeta<T>(key: MetaKey, value: T): Promise<void>; clearAll(): Promise<void>; // Settings → “Clear local data” }
  • BrowserStorageAdapter — IndexedDB database keyflow v1: object stores documents (keyPath id) and meta (settings, autosave buffers, quarantine). Every read passes parseStoredDocument; corrupt or unknown-version records go to the quarantine meta list and surface in Settings — they never crash the library or vanish silently.
  • DesktopStorageAdapter — same methods via invoke() to the Rust commands below; selected only when running inside the Tauri shell.
  • FakeDesktopStorageAdapter — a scriptable queue of results and failures (e.g. “next putDocument rejects with disk_full”), giving deterministic ack-error and recovery tests without a desktop host.
  • Autosave buffer — meta key autosave:{docId} holds { title, text, savedAt }, written on every debounce tick before the primary write. If the primary write fails or the app dies mid-save, the buffer is the recovery source.

Suggestions: adapter, deterministic local example, confirm-to-apply

export interface SuggestionAdapter { id: string; // "local-clarity" ships; the interface is the extension point label: string; analyze(input: { title: string; text: string }): Suggestion[]; } export interface Suggestion { id: string; // stable: `${ruleId}:${occurrenceIndex}` ruleId: string; // "double-space", "weasel-word", "long-sentence", "passive-marker" message: string; // human explanation, names the rule range: { start: number; end: number }; replacement: string; // "" for a deletion }

LocalClarityAdapter is the deterministic local example: fixed rule list — repeated spaces, weasel words from a fixed list, sentences over 40 words, passive “was …ed by” markers. Same input, same output, forever; no model, no request. It runs only when the user clicks Check with Local Clarity. Results open a review tray: each suggestion previews a before/after diff of its exact range; Accept applies exactly that replacement through the reducer (creating a 'suggestion' revision, undoable); Reject removes it. Text is never touched before an explicit accept — tests assert byte-identical text after analyze.

The states where data loss could hide: autosave/ack/recovery, import conflicts, and suggestion review. Each is a tested state machine, not a hope.

Autosave, acknowledgement, and crash recovery

Reopen logic: if a recovery buffer exists whose savedAt is newer than the document’s last acked updatedAt, the library shows a recovery banner before anything else. Restore replays the buffer through parseStoredDocument and commits a 'restore' revision; Discard clears the buffer and keeps the last acked text. Both choices are explicit; neither is silent.

Import decision path

  • .txt / .md → always a new document (title from first heading or filename), one 'import' revision.
  • .keyflow.json → parseStoredDocument; invalid or unknown-version → explicit rejection with the reason; library byte-unchanged (asserted before/after in tests).
  • Valid, new id → imported directly.
  • Valid, existing id → conflict dialog — Keep newer (default) / Overwrite / Import as copy. An older import can never overwrite a newer local document silently, and neither can a newer one.
  • Safety invariant: imported content is plain text everywhere. No HTML rendering, no dangerouslySetInnerHTML anywhere in the codebase — embedded markup or scripts in an import are inert characters, and a test proves it.

Suggestion review path

Click Check with Local Clarity → tray lists suggestions with rule names → each row previews its exact before/after diff → Accept applies one replacement (one 'suggestion' revision, one undo step), Reject drops it, Discard all closes the tray. Analyze never mutates the document; accept applies exactly range → replacement and nothing else.
